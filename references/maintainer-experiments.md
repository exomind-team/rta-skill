# Maintainer experiments — opt in

Read only for an explicitly requested performance investigation, benchmark, or
skill optimization. Normal publication does not require stage telemetry, a new
time ledger, repeated log reading, or timing explanations to the calling model.
Existing tools may retain naturally generated run metadata without adding Agent tasks.

## Compare the same work

Freeze the source scope, requested editing/visual standard and acceptance endpoint.
Distinguish raw conversion, structured transcript, reading-edited manuscript,
source review, practical coverage, package validation and delivered readable EPUB.
A change in these duties is not an algorithmic speedup. Preserve examples and
essential visual states; do not improve a time score by silently dropping work.

When a user supplies a time goal, keep it in the project/experiment. For example,
`elapsed_end_to_end / source_runtime <= 0.5` can be a soft goal while completeness
and fidelity remain the floor. Do not impose this particular ratio on other users,
PDF-only work, or tasks with no declared time budget.

For a requested experiment, reuse existing logs plus a small timer around the
actual tested command. Report wall elapsed and, when measured, peak resources and
machine runtime. Separate cold installation/model download from warmed inference.
Distinguish the cumulative work across corrections and format revisions from the
end-to-end elapsed interval: parallel stage durations must not be summed as if
they were sequential waiting time. Do not reset the total at each new version.
Track an actual scope change separately, retaining the prior history. Leave unknown
historical effort blank; file dates can reveal ordering but not active work.

## Bounded video experiment

The tested PyPI extractor already uses FFmpeg by default and compares reduced-size
frames. Its installed 0.1.1 implementation sends full-resolution BGR samples through
a pipe, then resizes them for comparison. An upstream reduced-size scan followed
by original-resolution extraction only at selected times is a candidate optimization,
not a proven replacement or a default change.

Compare the current route and the candidate on the same local representative
intervals and parameters. Include an actual source case where available: a clean
slide, progressive bullets, small software state/dialog, meaningful annotation,
and lecturer/webcam motion. Do not manufacture course evidence from synthetic tests.

Measure:

- whole extraction/selection/repair cost, not only a fast detection pass;
- wall time and actual RAM/disk use under the tested environment;
- retained reference teaching states, extra candidates and missed transitions;
- original-resolution legibility and exact sampled-frame/source relationships;
- failures, fallback/retry cost, and reproducible tool/version/parameter identity.

Synthetic video tests establish implementation behavior only. A historical selected
frame set is a bounded reference, not proof that all important source states were
ever selected. Retain the existing default unless the candidate improves measured
cost while meeting the agreed source-specific coverage. No unattended semantic
selection, automatic insertion, global install or shared-cache cleanup follows.

Prefer reusable narrow corrections after an observed failure. Keep private media,
real transcripts, benchmark outputs and machine-specific paths in the experiment
workspace; only code, synthetic tests and durable findings belong in the skill.
