# RTA — Read and Trace Anything

**把资料整理成能阅读、能学习、也能追溯的知识作品。**

一门课程、一份讲义或一组文章，往往同时包含讲解、案例、操作画面和作者自己的文字。RTA 帮助 Agent 把这些材料整理成结构清晰的阅读作品，同时保留来源与修改线索，让读者可以顺着正文学习，也能在需要时查回原处。

RTA 是一个 Agent Skill。当前默认交付是 EPUB 电子书；你也可以指定其他适合的产物。它的目标是在约定的资料范围内，让作品在知识学习与信息参考上尽可能承接原资料。这个目标需要逐项验证，不会因为文件转换成功就自动成立。

## 适合做什么

- **视频课或录音课**：整理转写、保留讲解和案例，把必要的课件或操作画面放到相应正文旁。
- **PDF、讲义与扫描资料**：保留章节、图表、公式和来源位置；扫描页按需要进行 OCR。
- **网页与文章**：将指定文章整理成章节，保留作者、原有结构与引用。
- **同一课程的多个版本**：区分不同录制与编辑修订，比较增减内容，按约定合编或分册。
- **已有电子书的修订**：改善阅读、来源导航或图文衔接，并保留旧版本及其批注。

如果你只想要摘要，可以直接告诉 Agent；不必要求它制作完整书稿。

## 怎么用

安装后，在支持 Agent Skills 的环境中调用 `$rta`，并告诉 Agent 资料位置、想覆盖的范围与交付形式。调用方式以所用客户端为准。

例如：

> 使用 $rta 整理这门园艺课程。请根据录音转写和课件制作一本 EPUB，保留老师的案例与操作步骤；对涉及操作的画面放在正文旁，课件完整图册放在书末。保留原文对照，标明无法确认的内容。

这个例子是虚构的。实际任务中，Agent 应先盘点已有材料：已有可用转写就复用；只有扫描页时才需要 OCR；缺少转写时再考虑 ASR。你可以先要求一章试读，确认阅读体验后再处理其余内容。

## 它怎样保留原意

RTA 把**原始资料、转写、校对正文和编辑说明**区分开来。整理时，重点保留讲者的论点、前提、否定、数字、案例、推理、练习和操作步骤；清除不承载意思的赘词，并保留有意义的强调和自我修正。

例如，原文说“保存后才能继续”，校对时不能因为句子更短就写成“可以继续”——前者的条件是教学内容的一部分。原文中的错误或听不清的地方，也不会只凭上下文猜成一个流畅句子。

书中的原文对照使用预先计算的静态差异，不依赖运行时 JavaScript。默认折叠的“原文 +N -M”显示从原文到校对版的增删规模；具体样式和位置可按你的阅读习惯调整。折叠的原文方便溯源，正文仍需要保留读者学习所需的信息。

## 图文与 Agent 阅读

操作课里，一张最终画面不一定能说明完整过程。RTA 会结合材料查找必要的初始状态、操作和结果，将承担教学作用的图片放在相应文字旁。需要保留全部课件页时，可以在书末提供图册，并与正文互相跳转、复用图片资源。

对于视频关键画面，推荐按需使用本地工具 `deck-extract==0.1.1` 提取候选帧与时间信息。**候选帧不等于已核实的插图**：画面是否清晰、是否对应文字以及有没有遗漏中间状态，仍需结合原视频审阅。采样时间也不自动等于页面出现的起始时间。

电子书可以附带当前版本的 Agent 阅读指引与来源记录，帮助 Agent 区分正文、原文对照、图像说明与不确定项。历史草稿和审阅日志留在私人工作区。

## 安装

将仓库克隆到支持 Agent Skills 的客户端的技能目录。例如，使用 `.agents/skills` 的环境可以执行：

```bash
git clone https://github.com/exomind-team/rta-skill.git ~/.agents/skills/rta
cd ~/.agents/skills/rta
```

如果客户端使用其他技能目录，请按客户端约定放置整个 `rta` 文件夹，保留 `SKILL.md`、`references/` 和 `scripts/` 之间的相对位置。

### 按需安装脚本依赖

阅读技能说明不需要先安装全部工具。需要运行静态差异脚本时，可以在仓库目录中创建隔离环境；Python 3.11 是本项目已使用的版本：

```bash
python -m venv .venv
```

在 macOS／Linux 上安装基础依赖：

```bash
.venv/bin/python -m pip install -r requirements.txt
```

在 Windows PowerShell 上：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

需要本地视频关键帧候选时，用同一个虚拟环境的 Python 按需安装 `requirements-video-extract.txt`。例如在 Windows PowerShell 上：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-video-extract.txt
```

视频画面复核可能还需要 FFmpeg 等工具。ASR、OCR、目标阅读器及 EPUB 检查器应根据具体材料和环境选择；RTA 不会因为启用技能就自动安装模型、上传音频或扫描整个资料库。工具安装与调用方式见 [制作流程](references/production-workflow.md) 和 [本地 ASR](references/asr-routing.md)。

## 如何判断成果是否可靠

RTA 将不同检查分别记录，避免把一种通过误解成全部通过：

| 检查 | 能回答的问题 | 不能单独证明 |
|------|-------------|-------------|
| 结构与差异回放 | 链接、配对和原文／校对文能否按约定还原 | 是否遗漏了案例或改变了意思 |
| 来源与正文审阅 | 检查过的内容是否保留了原资料中的意思 | 未检查的音频、画面或其他章节是否正确 |
| 图文与操作审阅 | 已检查的图片和文字能否说明相应步骤 | 所有未检查操作都已覆盖 |
| 阅读器检查 | 指定版本在指定阅读器中的显示与交互 | 其他设备、主题和版本均有相同表现 |
| 反馈后局部修订 | 读者报告是否绑定到具体版本、位置并按范围复查 | 单个读者的体验代表所有阅读器或读者 |

发布或交付时，应说明检查对象、范围、发现和未解决问题。EPUB 格式正确、统计数达标或测试通过，都不能单独证明读者已经能学会课程。

读者在交付后提出问题或新偏好时，按[反馈与版本维护流程](references/reader-feedback-and-maintenance.md)绑定到具体版本与位置，只复查受影响的部分。

## 隐私与边界

原始资料及项目审阅记录留在你选择的工作区；共享这个 skill 不需要附带课程、转写、截图或个人路径。是否使用云服务、安装依赖、导入 Zotero 或发布作品，由你和所用工具的授权范围决定。第三方工具有各自的行为，处理敏感资料前应检查其设置与数据流向。

交付后的读者反馈只在用户主动提供时处理；RTA 不要求遥测。反馈应绑定到具体版本和位置，并区分阅读体验、来源证据、实操充分性和新偏好。真实反馈与审阅记录留在私有工作区，公开回归样例使用虚构材料。

RTA 提供工作方法和辅助脚本，不是一个能够自动完成任意资料转换的统一命令行工具。目前 `SourceSet` 仍是规划中的整合格式，仓库没有提供统一的 SourceSet schema 或 `rta` CLI。`rta_trial.py` 是面向显式本地文件的实验性诊断工具；它不能验证来源真伪或代替人工审阅。`rta_scope_diff.py` 只核对 EPUB ZIP 成员改动是否符合 allowlist。自动挑图和无人值守插图仍待完善。
